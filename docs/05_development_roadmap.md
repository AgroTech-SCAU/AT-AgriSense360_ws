# AgriSense-360 全项目研发流程

版本：0.1  
日期：2026-09-30  
状态：执行中

## 1. 完成定义

项目“完成”不是只得到一张点云地图，而是同时满足：

1. EVT-1形成完整、高集成度设备，通过`04_integrated_scanner_rnd_baseline.md`的整机放行门槛；
2. ROS 2 Humble稳定采集LiDAR、IMU、多目图像、GNSS、电池、时间同步和整机状态；
3. 室内无GNSS、室外GNSS有效及短时失锁时，设备时间连续且同步状态可追溯；
4. 完成LiDAR-IMU建图、视觉融合、GNSS全局定位和农业场景验证；
5. 原始数据、标定、配置、固件和软件版本能够复现实验结果；
6. 形成原理图、PCB、BOM、结构、线束、装配、测试、操作与维护资料；
7. 发布可安装的软件版本、整机固件和至少一套验收数据集。

### 2.1 雷达先行不等于模块拼装

v0.2只启用MID360S和内置IMU，是最终整机软件架构的第一个可验证运行配置，不是另做一套独立雷达系统。实施期间遵守：

- 只维护一个`AT-AgriSense360_ws`，不创建独立的雷达工作空间；
- 从v0.2开始使用最终整机的`agrisense360_*`包名、话题命名、TF和统一启动入口；
- MID360S、MF287、GNSS和Scanner Mainboard按同一设备清单管理，后续只增加驱动和启用配置；
- 第三方驱动通过适配层接入，不让其话题和参数直接扩散到全部业务代码；
- v0.2输出的网络、时间戳、诊断和录包规则继续沿用到多传感器版本；
- v0.2通过只证明雷达惯导链路成熟，不代表EVT-1高集成整机完成。

软件分包是为了职责、测试和版本管理，不对应多个外置物理模块。最终用户只面对一个整机启动入口和一套设备状态。

## 3. 各工作流的执行顺序

### 3.1 软件与算法

```text
ROS 2工作区
  → MID360点云/IMU
  → rosbag2与数据质量检查
  → FAST-LIO2基础建图
  → 四目同步采集
  → 标定与视觉融合
  → GNSS全局约束
  → 农业语义/Global-LVBA/3DGS
  → 发布与回归测试
```

### 3.2 时间同步与固件

```text
接口实测
  → PPS捕获和相机Trigger
  → MID360 PPS/GPRMC生成
  → GNSS_LOCKED/HOLDOVER/LOCAL_SYNC
  → 曝光反馈与触发计数
  → 电源状态机/BMS/NUC关机握手
  → EVT-0报告
  → Scanner Mainboard固件
  → 故障注入和长期稳定性
```

### 3.3 硬件与结构

```text
实物型号与功耗测量
  → 电源/热/带宽预算
  → 原理图与接口评审
  → PCB和刚性传感器骨架
  → EVT-1装配
  → 板级、整机和标定测试
  → DVT整改
  → v1.0资料归档
```

## 4. 当前迭代：v0.2雷达惯导建图

当前只推进MID360/MID360S与内置IMU，不同时接入四目、GNSS融合或3DGS。

### 4.1 任务顺序

1. 拍照记录实物铭牌，冻结MID360或MID360S、序列号和固件；
2. 确认雷达IP、NUC网口IP、UDP端口、供电电压与峰值功耗；
3. 安装并固定版本的Livox-SDK2与`livox_ros_driver2`；
4. 验证点云和内置IMU话题、频率、QoS、frame_id与时间戳；
5. 录制静止、手持慢行、室内环路和室外短程四类rosbag2；
6. 评审并冻结一个ROS 2 Humble可维护的FAST-LIO2实现；
7. 完成话题、点类型、IMU单位、外参和时间配置适配；
8. 输出实时轨迹、点云地图、保存地图和bag回放结果；
9. 形成运行脚本、参数文件、问题记录与v0.2测试报告。

### 4.2 v0.2完成条件

- 点云和IMU连续运行不少于30分钟，无持续丢包或节点异常退出；
- rosbag2可以回放并重复得到一致的基础建图结果；
- 明确记录LiDAR到内置IMU的坐标定义和实际使用外参；
- 地图无明显发散、时间错位造成的重影或持续性分层；
- 一条命令能够启动驱动与建图，一条命令能够录制规定话题；
- 所有参数进入版本控制，不依赖未记录的手工修改。

## 5. 当前依赖决策

- `livox_ros_driver2`：官方支持ROS 2 Humble和MID360，可用于开发验证；官方同时提示其定位偏调试，产品版本需要进行稳定性评估和必要优化。
- `FAST_LIO`：HKU-MARS官方仓库当前主要面向ROS 1。项目必须先评审ROS 2移植版本或内部移植方案，再冻结提交号、许可证、消息类型和维护责任。
- 第三方代码统一放入`src/vendor/`或独立依赖工作区，自研包不得直接修改后失去来源记录。

## 6. 每个版本的共同验收材料

每次版本放行至少归档：

- 硬件/固件/软件/标定版本清单；
- 启动命令、参数和网络配置；
- 原始bag、关键日志与复现步骤；
- 指标结果、已知问题和回退方式；
- 接口变更和兼容性说明；
- 下一版本输入条件。
