# AgriSense-360 全项目研发流程

版本：0.2  
日期：2026-11-16  
状态：执行中（阶段三：原型验证）

## 1. 完成定义

项目“完成”不是只得到一张点云地图，而是同时满足：

1. EVT-1形成完整、高集成度设备，通过`04_integrated_scanner_rnd_baseline.md`的整机放行门槛；
2. ROS 2 Humble稳定采集LiDAR、IMU、多目图像、GNSS、电池、时间同步和整机状态；
3. 室内无GNSS、室外GNSS有效及短时失锁时，设备时间连续且同步状态可追溯；
4. 完成LiDAR-IMU建图、视觉融合、GNSS全局定位和农业场景验证；
5. 原始数据、标定、配置、固件和软件版本能够复现实验结果；
6. 形成原理图、PCB、BOM、结构、线束、装配、测试、操作与维护资料；
7. 发布可安装的软件版本、整机固件和至少一套验收数据集。

## 2. 四阶段研发路线

项目按“方案设计 → 硬件同步 → 原型验证 → 产品化修改”四个阶段推进，阶段内再按软件版本细分。阶段门禁不因单次演示、台架飞线或单个模块跑通而放宽。

| 阶段 | 状态 | 核心工作 | 放行条件 |
|---|---|---|---|
| 一、方案设计 | 已完成 | 产品定义、总体架构、接口契约、器件与风险清单 | 研发基准冻结，ROS 2 骨架可构建 |
| 二、硬件同步 | 基本完成，遗留项转入阶段三 | 时间主干、GNSS、相机触发、电源时序、示波器测量 | 同步链路电气验证通过，遗留项有明确关闭条件 |
| 三、原型验证 | **当前阶段** | 雷达惯导建图、四目同步采集、标定、视觉/GNSS 融合、农业场景 | 全部传感器稳定采集，标定与结果可复现 |
| 四、产品化修改 | 未开始 | Scanner Mainboard、结构/线束/BMS、DVT/PVT、认证与发布 | 通过 EVT-1 高集成放行门槛，资料闭环 |

### 2.1 阶段一：方案设计（已完成）

目标：冻结“做什么、怎么分层、接口是什么”，避免边做边改架构。

- 产品定义、整机边界与 EVT-0/EVT-1 分级；
- 硬件事实核验、功耗/带宽/存储预算与 P0 待确认清单；
- 坐标系、话题、启动入口、第三方依赖策略；
- 相关成果调研与技术路线选择。

放行条件：

- `04_integrated_scanner_rnd_baseline.md` v0.4 批准，`01`–`03` 形成基线；
- ROS 2 工作空间可构建，话题/坐标/标定契约进入版本控制；
- 未核验的型号、固件和接口保持 `UNCONFIRMED`。

### 2.2 阶段二：硬件同步（基本完成）

目标：在台架上证明“时间与触发”在电气层成立，为原型验证提供统一时基。

- GNSS PPS/GPRMC 输入与 TimeSyncV2 时间状态机；
- MID360S PPS/GPRMC 输出；
- MF287 单路 Trigger，四目同步曝光由相机内部 FPGA 完成；
- 电源上电/掉电时序、浪涌与示波器测量；
- 同步板状态只读上报到 ROS 2。

已完成：

- TimeSyncV2 只读轮询节点与 `TimeSyncStatus`；
- `/dev/agrisense-*` 稳定别名规则；
- GNSS NMEA 链路、LOCAL/GNSS 模式枚举；
- CAM1–CAM4 Trigger 脉冲输出。

遗留项（转入阶段三，关闭前不得视为硬件同步完成）：

- MF287 外触发/slave 固件或配置：需厂家提供，当前相机仍自由运行；
- GNSS 天线、PVT/UTC 锁定与 RTK 固定解；
- 示波器波形与端到端时间残差报告归档；
- udev 规则在目标机上的安装验证。

放行条件：示波器与端到端同步报告通过；遗留项有明确责任人和关闭条件。

### 2.3 阶段三：原型验证（当前）

目标：在 EVT-0 台架上把全部传感器与算法链路跑通，形成可复现的原型数据集和结论。允许使用开发板、临时线束和实验电源，但软件必须运行在最终的工作空间、话题和 TF 约定内。

| 子阶段 | 版本 | 核心工作 | 完成条件 |
|---|---|---|---|
| P3.1 雷达惯导建图 | v0.2 | MID360S 点云/IMU 接入，FAST-LIO2 适配与实机建图 | 连续运行 ≥30 min，回放可复现，地图无发散 |
| P3.2 四目同步采集 | v0.3 | 四目驱动、硬触发、图像与触发计数配对、内参采集 | 四路稳定，丢帧可检测，数据集完整 |
| P3.3 时间与标定 | v0.4 | PPS/GPRMC、Trigger、时间戳语义、Camera-IMU/LiDAR-Camera 标定 | 端到端残差达标，标定可复现 |
| P3.4 视觉融合建图 | v0.5 | FAST-LIVO2 或等价方案，彩色点云 | 彩色地图质量与配准达标 |
| P3.5 GNSS 全局定位 | v0.6 | 杆臂标定、RTK 状态、局部轨迹与全局坐标对齐、失锁/重锁 | 大范围轨迹连续，多次采集可对齐 |
| P3.6 农业场景验证 | v0.7 | 果园/农田数据、退化检测、农业语义；可选 Global-LVBA 与 3DGS | 完成代表性场景数据和指标报告 |

阶段放行条件：

- 全部传感器在单一工作空间、单一启动入口下稳定采集；
- 标定流程、参数和结果可复现，外参有测量或标定来源；
- 彩色地图、轨迹和同步指标达到 `04` 的验收要求；
- 至少一套真实农业场景数据集与测试报告归档；
- 阶段二遗留项全部关闭；
- 原始数据、配置、固件和软件版本能够复现实验。

### 2.4 阶段四：产品化修改（未开始）

目标：把验证过的原型收敛为可交付、可维护、可小批量生产的整机。

- v0.8 EVT-1 首版整机：Scanner Mainboard、刚性传感器头、统一结构/散热/线束、封闭电池组件、一键开关机；
- v0.9 DVT/PVT：故障注入、温升/振动/续航、产测工装、认证与整改；
- v1.0 发布：安装包、整机固件、操作/维护文档、验收数据集。

放行条件：通过 `04` §9.3 高集成放行门槛，需求追踪闭环，整机和软件可交付。

### 2.5 雷达先行不等于模块拼装

v0.2只启用MID360S和内置IMU，是最终整机软件架构的第一个可验证运行配置，不是另做一套独立雷达系统。实施期间遵守：

- 只维护一个`AT-AgriSense360_ws`，不创建独立的雷达工作空间；
- 从v0.2开始使用最终整机的`agrisense360_*`包名、话题命名、TF和统一启动入口；
- MID360S、MF287、GNSS和Scanner Mainboard按同一设备清单管理，后续只增加驱动和启用配置；
- 第三方驱动通过适配层接入，不让其话题和参数直接扩散到全部业务代码；
- v0.2输出的网络、时间戳、诊断和录包规则继续沿用到多传感器版本；
- v0.2通过只证明雷达惯导链路成熟，不代表EVT-1高集成整机完成。

软件分包是为了职责、测试和版本管理，不对应多个外置物理模块。最终用户只面对一个整机启动入口和一套设备状态。

## 3. 各工作流的执行顺序

### 3.1 软件与算法

```text
ROS 2工作区
  → MID360S点云/IMU
  → rosbag2与数据质量检查
  → FAST-LIO2基础建图
  → 四目同步采集
  → 标定与视觉融合
  → GNSS全局约束
  → 农业语义/Global-LVBA/3DGS
  → 发布与回归测试
```

### 3.2 时间同步与固件

```text
接口实测
  → PPS捕获和相机Trigger
  → MID360 PPS/GPRMC生成
  → GNSS_LOCKED/HOLDOVER/LOCAL_SYNC
  → 曝光反馈与触发计数
  → 电源状态机/BMS/NUC关机握手
  → EVT-0报告
  → Scanner Mainboard固件
  → 故障注入和长期稳定性
```

### 3.3 硬件与结构

```text
实物型号与功耗测量
  → 电源/热/带宽预算
  → 原理图与接口评审
  → PCB和刚性传感器骨架
  → EVT-1装配
  → 板级、整机和标定测试
  → DVT整改
  → v1.0资料归档
```

## 4. 当前迭代：v0.2雷达惯导建图（阶段三 P3.1）

当前只推进MID360S与内置IMU，不同时接入四目融合、GNSS融合或3DGS。

### 4.1 任务顺序

1. 拍照记录实物铭牌，冻结MID360S序列号和固件；
2. 确认雷达IP、NUC网口IP、UDP端口、供电电压与峰值功耗；
3. 安装并固定版本的Livox-SDK2与`livox_ros_driver2`；
4. 验证点云和内置IMU话题、频率、QoS、frame_id与时间戳；
5. 录制静止、手持慢行、室内环路和室外短程四类rosbag2；
6. 评审并冻结一个ROS 2 Humble可维护的FAST-LIO2实现；
7. 完成话题、点类型、IMU单位、外参和时间配置适配；
8. 输出实时轨迹、点云地图、保存地图和bag回放结果；
9. 形成运行脚本、参数文件、问题记录与v0.2测试报告。

### 4.2 v0.2完成条件

- 点云和IMU连续运行不少于30分钟，无持续丢包或节点异常退出；
- rosbag2可以回放并重复得到一致的基础建图结果；
- 明确记录LiDAR到内置IMU的坐标定义和实际使用外参；
- 地图无明显发散、时间错位造成的重影或持续性分层；
- 一条命令能够启动驱动与建图，一条命令能够录制规定话题；
- 所有参数进入版本控制，不依赖未记录的手工修改。

### 4.3 当前进展

- 工作空间、固定提交的依赖、构建白名单和离线回放链路已就绪；
- `scanner_control_driver` 已提供同步板只读状态；
- 相机 SDK 仅构建 `ros2/src/data_cap`，标定工具链以容器方式固定；
- 待完成：实机 MID360S 网络/固件核验、实机建图、MF287 外触发固件。

## 5. 当前依赖决策

- `livox_ros_driver2`：官方支持ROS 2 Humble和MID360，可用于开发验证；官方同时提示其定位偏调试，产品版本需要进行稳定性评估和必要优化。
- `FAST_LIO`：HKU-MARS官方仓库当前主要面向ROS 1。项目必须先评审ROS 2移植版本或内部移植方案，再冻结提交号、许可证、消息类型和维护责任。
- `CyperstereoSDK`：仅使用 `ros2/src/data_cap`；ROS 1 包、`Fast-ISP`、工具和样例不进入 colcon 构建。
- `kalibr`：ROS 1/catkin，只在 Noetic 容器中运行，不导入 Humble 工作空间。
- 第三方代码统一放入`src/vendor/`或独立依赖工作区，自研包不得直接修改后失去来源记录。

## 6. 每个版本的共同验收材料

每次版本放行至少归档：

- 硬件/固件/软件/标定版本清单；
- 启动命令、参数和网络配置；
- 原始bag、关键日志与复现步骤；
- 指标结果、已知问题和回退方式；
- 接口变更和兼容性说明；
- 下一版本输入条件。
